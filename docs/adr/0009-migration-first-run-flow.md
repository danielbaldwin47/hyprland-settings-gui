# ADR-0009: Migration & first-run flow

**Status:** accepted — 2026-08-19

## Context

ADR-0002 made the migration wizard a headline feature; ADR-0005 fixed the file layout and
backup story; ADR-0006 punted `hyprctl dispatch` breakage to this flow's loss report. The
importer prototype (#9) settled feasibility and left hard constraints:

- Hyprland loads `hyprland.lua` over `hyprland.conf` when both exist, never both; `hyprctl
  reload full-reset` switches engines mid-session.
- **First launch is consumed** (`lastVersion`, `hl.permission`, donate screen): two configs
  cannot be A/B-compared fairly in one `$HOME`. Verification must happen against the live
  session, with rollback as the safety net — not by pre-comparison.
- `Hyprland --verify-config` parses either engine without a compositor: a cheap static gate.
- `hyprctl dispatch` is engine-swapped: legacy dispatch syntax breaks the moment the config
  becomes Lua — in scripts, bars, and the config's own `exec` strings. The wizard cannot fix
  this; it can only find and report it.
- `# hyprlang if` branches are evaluated **at conversion time** and baked in; dead keysyms
  are silently inert under hyprlang but fatal under Lua; `catchall` loses modifiers.
- `hl.env` is sticky and `hl.permission` first-launch-only: neither takes effect on reload.
- `code:N` binds are invisible to `hyprctl binds` (ADR-0007): bind verification counts from
  generated source, not IPC read-back.
- Positioning (user, this ticket): the app must not feel like a one-way "help me leave
  hyprlang" tool, and must never *demolish* an existing config or demand you delete your own
  file to make the GUI work. Interop is the feature: any config in, plain Lua out.

## Decision

### First-run detection

On every app start, exactly one of four cases holds:

1. **App-generated `hyprland.lua`** (Manifest hash matches) — normal run.
2. **Foreign `hyprland.lua`** — the **Lua import** flow is auto-offered: the file is treated
   as the current settings and imported into the App dir; the original is renamed
   `hyprland.lua.bak` as the rollback target. It is *not* adopted as a `user.lua` override —
   an app that is inert until you delete your own config is no app at all.
3. **Only `hyprland.conf`** — the **migration wizard** over the hyprlang Importer. A conf
   bearing Hyprland's `autogenerated = 1` marker gets the streamlined variant: no loss
   report, straight to convert (it is Hyprland's own example, not the user's work).
4. **Neither** — fresh start: generate an empty App dir (every Option Unset) and Entrypoint.

Until an offered import/migration is accepted, settings pages are visible but read-only with
a dismissible banner ("You are still on hyprland.conf — settings can't be saved yet.
Convert…") and an app-menu entry. No nagging beyond that.

### One wizard, two importers

Five steps, each an `Adw.NavigationView` subpage in one dialog (prototyped in #7):
**Detect → Preview → Back up → Switch & verify → Keep or roll back.**

- **`.conf` source:** the hyprlang Importer (prototype-proven, 7/7 corpus rices verify
  clean). Variables land in `vars.lua`; unrepresentable constructs in `legacy.lua`.
- **`.lua` source:** the **Lua importer** — evaluation-based. The file is executed under a
  recording `hl.*` stub: declarative calls (`hl.config`, `hl.bind`, `hl.monitor`, rules, …)
  are captured into the model; script constructs (`hl.on` handlers, function-valued actions,
  `hl.plugin` logic) are extracted by source range into `legacy.lua`. Conditionals and loops
  *execute* — their result is baked, reported exactly like `# hyprlang if`. This importer is
  a new risky piece and gets its own prototype before the spec.
- Either way, every key present in the source is marked **set** (ADR-0005 tri-state), and
  import provenance (date, source hash) lands in the Manifest.

### Preview & loss report

The preview shows a per-file before/after diff plus the **loss report**, in three classes:

| Class | Contents |
| --- | --- |
| **Info** | Converted with a semantics note (e.g. `exec-once` → `hl.on('hyprland.start')`). |
| **Needs review** | Baked decisions shown with the branch taken: `# hyprlang if` conditions, dead keysyms (xkb-validated, commented out), `catchall` modifier loss, gesture `dispatcher` → callback. |
| **Breakage** | What the wizard cannot fix: `hyprctl dispatch`/`keyword` greps across all exec strings *and referenced local scripts*; external tools with no Bridge. |

The report is persisted to `$XDG_STATE_HOME/hyprtweaker/reports/<timestamp>.{md,json}` and
reachable later from the app menu. A "Copy the Lua instead" exit serves DIY users without
switching anything — interop, not lock-in.

### Back up, bridge, static gate

- Full copy of `~/.config/hypr/` to `$XDG_STATE_HOME/hyprtweaker/backups/<timestamp>/`
  (ADR-0005 — the design mockup's `~/.config/hypr.backup-*` location is superseded).
- `.conf` path: the conf tree stays in place untouched. `.lua` path: the foreign file is
  renamed `hyprland.lua.bak` beside itself (the filename is contested by the Entrypoint;
  a rename, never a delete).
- Bridge setup (ADR-0006) happens here: detected tools offered per-tool, each flip behind
  explicit confirmation.
- **Static gate:** the generated tree is written and `Hyprland --verify-config` must pass;
  failure stops the wizard before the live engine is touched.

### Switch & verify

Requires a live session; without an IPC socket the wizard runs Detect/Preview only.

1. Write a `migration-pending` sentinel to the state dir, then the Entrypoint.
2. `hyprctl reload full-reset`; treat socket2 `configreloaded` as "reload started", then poll.
3. Live checks over the IPC socket (spoken directly — no `hyprctl` spawns): `configerrors`
   empty; bind count vs model (`code:N` counted from source); monitor arrangement matches;
   window/layer/workspace rule counts match. `hl.env`/`hl.permission` are excluded and noted
   as "applies at next login"; autostart entries are noted as possibly re-run by the switch.
4. Any hard check fails → automatic rollback, report shown.

### Keep or roll back

- **1-minute countdown; doing nothing rolls back** (short by design: a broken-binds session
  should not strand the user for five minutes). Rollback = restore the previous engine:
  delete the Entrypoint (`.conf` path) or restore `hyprland.lua.bak` (`.lua` path), reload
  full-reset, clear the sentinel. **Keep** clears the sentinel.
- Crash safety: if the app relaunches and finds an unconfirmed sentinel, the switch is
  treated as failed and rollback is offered.
- The TTY rescue line is printed in every report: `rm ~/.config/hypr/hyprland.lua` (or
  `mv hyprland.lua.bak hyprland.lua`).
- Rollback stays available from the app menu for as long as the backup exists; restoring any
  backup replays Back up → Switch → Verify in reverse.

### Import / export — ongoing, not just first run

- **Import…** accepts any `hyprland.lua` or `hyprland.conf` at any time and runs the same
  wizard (fresh backup, preview, loss report, verify, rollback timer) before replacing the
  model.
- **Export…** writes a single self-contained `hyprland.lua`: Modules concatenated in require
  order, `vars` inlined, header comment — runs on any Hyprland ≥ 0.56 with no app installed.
  Export → Import round-trips onto another machine.

## Consequences

- The Lua importer is a fourth risky piece — prototyped before the map closes, like the
  other three.
- Importing Lua bakes runtime conditionals; the loss report is what keeps that honest.
- The 1-minute idle-rollback makes a bad switch cheap, at the cost of one extra click
  ("Keep") on every successful migration.
- Export flattens module structure by design: portability over structure.
- The read-only-until-converted state adds a mode to every settings page, but is what lets
  the app launch usefully on an unmigrated box.

## Alternatives considered

- **Adopt a foreign `hyprland.lua` as `user.lua`** (escape-hatch override) — rejected by the
  user: the GUI would be inert until the user deletes their own config; feels proprietary.
- **Nested-Hyprland A/B pre-verify in the wizard** — rejected: ~45 s, needs nested support,
  and first-launch consumption makes the comparison unfair anyway. It lives in the importer
  test harness (#16) instead.
- **Idle = keep on the countdown** — rejected: a session with broken binds strands the user.
- **5-minute countdown** — rejected by the user in favour of 1 minute.
