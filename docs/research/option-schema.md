# Research: option schema sources and type inference

Read by the agent working in `engine/schema` or the Overlay, when a ticket names a section here. Resolves issue #3 (part of #1). Question: how completely can the 353 `hyprctl -j descriptions`
entries be turned into a typed, documented, grouped schema for auto-generated settings pages, and
where must the schema be hand-curated?

Date: 2026-08-19. Hyprland `0.56.2` (`hyprctl version`: commit `efb5099`), stubs
`/usr/share/hypr/stubs/hl.meta.lua` (autogenerated by `meta/generateLuaStubs.py`), wiki checkout
`hyprland-wiki@2e15371` (2026-08-18). Machine-readable companion:
[`option-schema.coverage.json`](./option-schema.coverage.json) (one record per option: source type,
stub type, inferred widget, min/max/map/choices, refresh bits, device-overridable, wiki match,
curation notes).

Sources (all primary):

- `S1` `hyprctl -j descriptions` (live, 353 entries) and `hyprctl -j getoption <name>` (swept over all 353).
- `S2` Hyprland `v0.56.2`: `src/config/values/ConfigValues.cpp` (`jsonify`, the `MS<T>` table),
  `src/config/values/ConfigValues.hpp`, `src/config/values/types/*.{hpp,cpp}`,
  `src/config/ConfigValue.hpp`, `src/config/legacy/ConfigManager.cpp`, `src/config/lua/ConfigManager.cpp`,
  `src/config/supplementary/propRefresher/PropRefresher.{hpp,cpp}`, `src/debug/HyprCtl.cpp`,
  `src/config/shared/complex/ComplexDataTypes.hpp`, `meta/generateLuaStubs.py`
  (raw URLs: `https://raw.githubusercontent.com/hyprwm/Hyprland/v0.56.2/<path>`).
- `S3` `/usr/share/hypr/stubs/hl.meta.lua` (`HL.ConfigKey` L38-395, `HL.ConfigValueTypes` L957-1311, `HL.ConfigOpt.*` L1314+).
- `S4` wiki `content/Configuring/Basics/Variables.md` and `content/Configuring/Layouts/{Dwindle,Master,Scrolling}-Layout.md`.
- `S5` hyprlang `main`: `src/config.cpp`, `src/common.cpp` (semantics of `set`).

## TL;DR

1. `descriptions` carries **no type field**. Type must be inferred from JSON field *shape*
   (`jsonify`, `ConfigValues.cpp:28-146`). Shape alone separates 6 classes; the remaining ambiguity
   (`String` vs `Color` vs `Gradient` vs `FontWeight`, all emitted as a JSON string) is resolved by
   the stub (`HL.ConfigValueTypes`) for Gradient/FontWeight, and only by the C++ source (`MS<Color>`)
   for Color vs String. Result: **all 353 options can be typed exactly** by combining
   `descriptions` + stub + one regex pass over `ConfigValues.cpp`.
2. **`descriptions.current` is not the live value in 0.56.2.** For Bool/Float it is always
   `false`/`0`; for every other type it equals `default`. Nobody calls `IValue::commence()` in the
   legacy (hyprlang) or Lua config manager, so `m_val.good()` is false and `value()` returns
   the default (`IntValue.cpp:21`) or literally `false` (`BoolValue.cpp`, `FloatValue.cpp`).
   Verified: 127/353 mismatches between `descriptions.current` and `getoption` on this machine.
   Use `getoption` for current values.
3. `getoption` reports `int` (Bool, Int, Color), `float`, `str`, `vec2`, `custom` (Gradient,
   CssGap, FontWeight) plus `set` = hyprlang `m_bSetByUser` (true iff the key was assigned in the
   config or via `hyprctl keyword` since the last reload; independent of whether the value equals
   the default). "Is default" must be computed by comparing against `descriptions.default`.
4. Refresh bits (`REFRESH_LAYOUTS`, ...) exist only in the C++ table; they are not exported by
   `descriptions`, `getoption` or the stub, and at reload time everything is refreshed with
   `REFRESH_ALL` anyway. "Requires restart" exists only as prose in the wiki (10 rows).
5. Wiki coverage: 351/353 options documented; 148 have longer descriptions than `descriptions`,
   129 identical. 14 wiki rows are newer than 0.56.2 (`decoration:wobble:*`, ...). Section-level
   `[!NOTE]` blocks are not row-parseable but the tables are.
6. Coverage: 292/353 (83%) can be widgetised purely from generated data; 61 need a curated overlay
   (enum labels for map-less ints, known-values for strings, sentinels, pickers, vec2 ranges);
   27 belong to sections to hide by default (`debug`, `quirks`, `experimental`, `input-capture`).

## 1. Type inference rules

### 1.1 What `descriptions` actually emits (S2 `ConfigValues.cpp:28-146`)

`jsonify()` dynamic-casts each `IValue` and prints a per-type template. Field shapes:

| C++ value class | JSON `default`/`current` | extra keys | example (S1) |
|---|---|---|---|
| `CBoolValue` | JSON `true`/`false` | none | `general:no_focus_fallback` |
| `CIntValue` | JSON number | `min`, `max`, `map` (each may be `null`) | `general:border_size` `{min:0,max:20,map:null}` |
| `CFloatValue` | JSON number | `min`, `max` (no `map`) | `decoration:active_opacity` `{min:0,max:1}` |
| `CCssGapValue` | JSON string `"t r b l"` | `min`, `max` (always `null` in 0.56.2) | `general:gaps_in` `"5 5 5 5"` |
| `CFontWeightValue` | JSON string, integer text | none | `group:groupbar:font_weight_active` `"400"` |
| `CGradientValue` | JSON string `"<argbhex> [<argbhex> ...] <N>deg"` | none | `general:col.active_border` `"ffffffff 0deg"` |
| `CStringValue` | JSON string | none | `general:layout` `"dwindle"` |
| `CVec2Value` | JSON array `[x, y]` | none | `decoration:shadow:offset` `[0, 0]` |
| `CColorValue` | JSON string, `{:x}` of the int64 (ARGB) | none | `misc:background_color` `"ff111111"`, sentinel `"-1"` |

Notes:

- The `map` value is an array of single-key objects, `[{ "disable": 0 },{ "top_left": 1 }, ...]`
  (`ConfigValues.cpp:13-25`, `opt<OptionMap>`); order is unordered_map order, so sort by value.
- Gradient/CssGap/FontWeight text is `IComplexConfigValue::toString()` (`ComplexDataTypes.hpp:69-76, 133-135, 154-156`).
- Sentinels are lossy in `descriptions`: `MS<Gradient>("decoration:shadow:color_inactive", ..., -1, ...)`
  (`ConfigValues.cpp:213`) prints as `"ffffffff 0deg"`; `MS<Color>` with `-1` prints `"-1"`;
  strings default to `"[[EMPTY]]"` (`StringValue.hpp` `m_default`) or `"[[Auto]]"`.
- Descriptions are raw C string literals dropped into JSON without escaping (`x->description()`);
  none of the 353 currently contains `"` or `\`, but the parser should be tolerant.
- Empirical shape survey (S1 vs `MS<T>` in S2), 353/353 consistent:
  `bool`=174 Bool, `list2`=6 Vec2, `num+min/max`=34 Float, `num+min/max+map`=84 Int,
  `str+min/max`=3 CssGap, `str`=52 (6 Color + 2 FontWeight + 16 Gradient + 28 String).

### 1.2 What the stub adds (S3, generated by `meta/generateLuaStubs.py:253-275`)

`parse_config_values` regexes `MS<([A-Za-z0-9_]+)>\("([^"]+)"` out of `ConfigValues.cpp` and maps
type -> Lua type; keys are rewritten `:`->`.` and `-`->`_`:

| `MS<T>` | stub type (`HL.ConfigValueTypes`) | count |
|---|---|---|
| Bool | `boolean` | 174 |
| Int | `integer\|boolean` | 84 |
| Float | `number\|boolean` | 34 |
| String | `string` | 28 |
| Color | `string` | 6 (indistinguishable from String in the stub) |
| Gradient | `string\|HL.Gradient` | 16 |
| Vec2 | `HL.Vec2Like` | 6 |
| CssGap | `integer\|HL.CssGap` | 3 |
| FontWeight | `integer\|string` | 2 |

Cross-check: `HL.ConfigKey` (353 keys) == `descriptions` names after `:`->`.`, `-`->`_`
(the only 4 renamed keys: `input.touchpad.tap_to_click`, `input.touchpad.tap_and_drag`,
`input_capture.capture_modifiers`, `input_capture.enforce_barriers`). No option exists in only one
of the two. The stub also gives the nesting tree (`HL.ConfigOpt.General.Snap`, `...Decoration.Blur`,
`...Group.Groupbar.Col`, ...) which is a ready-made page/subsection grouping.

### 1.3 Additional metadata only in `ConfigValues.cpp` (S2)

- Enum maps for 30 Ints (`.map = OptionMap{...}`) - these ARE exported in `descriptions.map`.
- `strChoice({...})` validators on 3 Strings (`ConfigValues.hpp:33-46`): `input:accel_profile`
  `[adaptive/flat/custom]`, `input:scroll_method` `[2fg/edge/on_button_down/no_scroll]`,
  `input:touchpad:tap_button_map` `[lrm/lmr]`. Not exported, but each also repeats the list in its
  description text in `[a/b/c]` form.
- `vec2Range(minX,minY,maxX,maxY)` validators on all 6 Vec2 (`ConfigValues.hpp:24-31`): not
  exported. Values: shadow:offset ±250, tablet:region_position ±20000, tablet:region_size
  [-100,4000], tablet:active_area_* [0,500], layout:single_window_aspect_ratio [0,1000].
- `.refresh = REFRESH_*` bits on 127 options (see section 5). Not exported.
- `CONFIG_DEVICE_VALUE_NAMES` (`ConfigValues.hpp:123-175`): 50 `input:*` options that can be
  overridden per device (`device { }` special category, `legacy/ConfigManager.cpp:518-565`).
  Useful for a "per-device" badge.
- Nothing distinguishes "advanced"/"dangerous" options; only the section name does.

### 1.4 Widget inference rules (in priority order)

Given a `descriptions` record `o`, its stub type `st`, and (optional) the source-derived record `src`:

| # | condition | widget kind | count |
|---|---|---|---|
| R1 | `o.default` is JSON bool | `toggle` | 174 |
| R2 | `o.default` is JSON array of 2 numbers | `vec2` (two numeric fields; range from overlay/source `vec2Range`) | 6 |
| R3 | `o` has key `map` and `map != null` | `enum-map` (dropdown/segmented, label=key, value=int; also honour `min/max`) | 30 |
| R4 | `o` has key `map` (== null) and numeric `min` and `max` and `max < 2^31-1` | `int-range` (spin/slider) | 52 |
| R5 | `o` has key `map` otherwise | `free-int` (spin, no slider) - `binds:drag_threshold` (max INT_MAX), `input:tablettool:eraser_button_override` (max null) | 2 |
| R6 | numeric default, keys `min`,`max` but no `map` key, both non-null | `float-range` (slider + decimal spin; step from default's decimals) | 33 |
| R7 | numeric default, `min`/`max` null | `free-float` - `input:follow_mouse_threshold` | 1 |
| R8 | string default and keys `min`,`max` present | `css-gaps` (1/2/3/4-value editor, `t r b l`) | 3 |
| R9 | string default and `st == "string\|HL.Gradient"` | `gradient` (>=1 ARGB colours + angle) | 16 |
| R10 | string default and `st == "integer\|string"` | `font-weight` (preset names + 100..1000) | 2 |
| R11 | string default, `st == "string"`, `src.type == "Color"` (or overlay says color) | `color` (single ARGB, `-1` sentinel = "unset/fallback") | 6 |
| R12 | string default, `src.choices` present or description matches `\[[^\]]+/[^\]]+\]` | `enum-string` / `string-known-values` (combo, editable when list is open-ended e.g. `lua:<name>`) | 3 + 3 |
| R13 | string default otherwise | `string` (free text; overlay may upgrade to font/monitor/file/regex picker) | 22 |

Without the C++ source (R11), Color would fall through to `string` for 6 options; the overlay can
carry that bit if we don't want a build-time dependency on the Hyprland tree. Everything else is
derivable from `descriptions` + stub only.

Heuristics that are worth applying automatically on top of the rules:

- Int with `max <= 6` and no `map` -> render as segmented control but flag for label curation
  (13 options, list in section 3).
- Description containing `[a/b/c]` -> known values (5 options: 4 strings + `misc:force_default_wallpaper`).
- Description containing backticked words for Strings -> known values (`master:new_status`, `master:new_on_active`).
- Default `"[[EMPTY]]"`/`"[[Auto]]"`/`"-1"`/`-1` -> render as "unset" placeholder rather than the literal.

## 4. How `getoption` reports each type; deriving "is default"

`dispatchGetOption` (`HyprCtl.cpp:1647-1731`) looks the name up with `Config::mgr()->getConfigValue()`
(`legacy/ConfigManager.cpp:1169-1184`, returns `{dataptr, type, setByUser}`) and switches on the
*runtime* type index, which is the hyprlang storage type, not the `MS<T>` class:

| `MS<T>` | registered as (`legacy/ConfigManager.cpp:488-511`) | JSON key | observed (S1 sweep of 353) |
|---|---|---|---|
| Bool | `Hyprlang::INT{0/1}` | `"int"` | 174 x `int` (0/1). The `"bool"` branch never fires under hyprlang. |
| Int | `Hyprlang::INT` | `"int"` | 84 |
| Color | `Hyprlang::INT` (ARGB) | `"int"` (e.g. `4294967295`, `-1`) | 6 |
| Float | `Hyprlang::FLOAT` | `"float"` (`{:2f}`) | 34 |
| String | `Hyprlang::STRING` | `"str"` | 28 |
| Vec2 | `Hyprlang::VEC2` | `"vec2": [x,y]` | 6 |
| Gradient / CssGap / FontWeight | `CConfigCustomValueType` | `"custom": "<toString()>"` | 16 / 3 / 2. The `"gradient"`, `"css"`, `"font_weight"` branches never fire under hyprlang. |

So the `getoption` key alone cannot distinguish Bool/Int/Color, nor Gradient/CssGap/FontWeight;
the schema (from section 1) must supply the type and the parser for `custom`.

`set` (`VAR.setByUser`) is hyprlang `CConfigValue::m_bSetByUser` (`hyprlang include/hyprlang.hpp:278`):
set to `true` whenever a value is assigned by parsing (`hyprlang src/config.cpp:527`; this includes
`hyprctl keyword`), reset to `false` for every value at the start of each `parse()`/reload
(`config.cpp:925-936` -> `defaultFrom`, `src/common.cpp:79-123`). It does **not** compare values:
`general:resize_on_border = false` in this machine's config yields `int: 0, set: true`.

Therefore:

- **current value**: `getoption` (per option, or 353 calls in a batch - `hyprctl --batch` works, but
  output separation is by concatenation; simpler to call per option or cache).
- **is-default**: `parse(getoption) == parse(descriptions.default)` using the per-type parser
  (Bool: `int!=0` vs bool; Color: `int & 0xffffffff` vs hex, `-1` sentinel special-cased; Float:
  epsilon; Gradient/CssGap/FontWeight: string equality of the `toString()` forms, since
  `descriptions.default` uses the same `toString()`).
- **explicitly set in config**: `set` - independent, useful for a "reset to default" affordance
  and for showing "(from your config)" vs "(default)".
- Do not use `descriptions.current` (broken in 0.56.2, see TL;DR 2). If a later version fixes
  `commence()`, it would still only be a snapshot at query time, so `getoption` remains the source of truth.
- Names must be given in colon form (`input:touchpad:tap-to-click`); the Lua-style dot/underscore
  names from the stub must be mapped back.

## 5. Refresh / restart metadata

- Defined: `Config::Supplementary::ePropRefreshProp` (`PropRefresher.hpp:9-21`): `REFRESH_LAYOUTS`,
  `REFRESH_INPUT_DEVICES`, `REFRESH_SCREEN_SHADER`, `REFRESH_BLUR_FB`, `REFRESH_RULES`,
  `REFRESH_WINDOW_STATES` (implies RULES), `REFRESH_MONITOR_STATES` (implies LAYOUTS),
  `REFRESH_CURSOR_ZOOMS`, `REFRESH_CONFIG_WATCHER`, `REFRESH_GRADIENTS_GROUPBAR`, `REFRESH_ALL`.
- Attached per option via `.refresh =` in the `MS<T>` options struct, stored in `IValue::m_refreshProps`
  (`IValue.hpp:15`), readable via `refreshBits()`. Distribution in 0.56.2: INPUT_DEVICES 56,
  WINDOW_STATES 32, BLUR_FB 18, LAYOUTS 15, GRADIENTS_GROUPBAR 4, SCREEN_SHADER 1, MONITOR_STATES 1,
  CONFIG_WATCHER 1, CURSOR_ZOOMS 1; 226 options have no bits.
- **Not exposed anywhere**: `jsonify` does not print them, `getoption` does not, the stub does not,
  and the wiki does not mention them. On a legacy config reload the manager schedules
  `REFRESH_ALL` (`legacy/ConfigManager.cpp:1070`; Lua manager `lua/ConfigManager.cpp:850`), so
  per-option bits only matter for the Lua `hl.config()` incremental path. For the GUI the
  practical meaning is: after writing the config, a reload refreshes everything that can be
  refreshed at runtime; the bits could be harvested from source into the generated schema as
  informational "what will be recomputed", but nothing in them says "needs restart".
- "Requires restart" is wiki prose only (section 2 list: `render:cm_enabled`,
  `render:commit_timing_enabled`, `debug:gl_debugging`, `debug:full_cm_proto`,
  `xwayland:create_abstract_socket`; monitor-reload: `misc:disable_splash_rendering`,
  `misc:col.splash`, `misc:splash_font_family`). Keep as an overlay field, seeded from the wiki regex,
  hand-verified.
- The event bus emits `config.props_refreshed` / `config.reloaded` (stub `HL.EventName`, L6-7)
  and the IPC socket2 emits `configreloaded` (`legacy/ConfigManager.cpp:1074`) - usable to
  re-poll `getoption` after a save.

## 6. Recommendation: schema layer

Two files, both checked into the repo, keyed by Hyprland version:

### 6.1 Generated: `schema/hyprland-<version>.json`

Produced by a script that runs against (a) `hyprctl -j descriptions` from a running compositor of
that version, (b) the installed `hl.meta.lua`, and optionally (c) a checkout/tarball of the
Hyprland source at that tag for the bits not exported (Color vs String, `strChoice`, `vec2Range`,
refresh bits, device-overridable list). If (c) is unavailable the generator degrades to
"string" for Color and leaves ranges empty; the overlay fills the gaps.

Per option:

```jsonc
{
  "name": "general:border_size",          // colon form (hyprctl / hyprlang key)
  "lua_key": "general.border_size",        // stub key (HL.ConfigKey)
  "path": ["general", "border_size"],      // from HL.ConfigOpt tree (nesting = subsection)
  "type": "int",                           // bool|int|float|string|color|gradient|vec2|css_gaps|font_weight
  "widget": "int-range",                   // rule R1-R13 output
  "description": "size of the border around windows",
  "default": 1,                            // parsed, typed (sentinels normalised: null for -1/[[EMPTY]]/[[Auto]])
  "default_raw": 1,                        // exactly what descriptions printed
  "min": 0, "max": 20,                     // ints/floats/css_gaps; vec2 from vec2Range when source available
  "map": {"disable": 0, ...},              // enum-map, sorted by value
  "choices": ["adaptive","flat","custom"], // strChoice or [a/b/c] regex
  "getoption_key": "int",                  // int|float|str|vec2|custom
  "device_overridable": false,
  "refresh": ["REFRESH_WINDOW_STATES"],    // informational
  "since": "0.56.2"                        // first version seen; lets the UI grey out unknown options
}
```

Plus a per-version diff of added/removed/retyped options (the wiki-only list above shows the
churn between 0.56.2 and main is ~14 options).

### 6.2 Hand-curated overlay: `schema/overlay.json` (version-independent, keyed by `name`)

Proposed fields (all optional, all override the generated record):

| field | purpose | seeded from |
|---|---|---|
| `title` | human label ("Border size" instead of `border_size`) | name -> title case |
| `help` | long-form help (markdown) | wiki row description when longer than `descriptions`, plus section-level notes |
| `help_url` | wiki anchor (`https://wiki.hypr.land/Configuring/Basics/Variables/#general`) | section |
| `widget` | override rule output (`segmented`, `font-picker`, `monitor-picker`, `xkb-layout`, `file`, `regex`, `float-list`, ...) | section 3 |
| `labels` | value->label map for map-less ints and for `map` keys that need prettier text (`Disabled`/`Enabled` capitalisation is inconsistent in source) | section 3.2 |
| `known_values` | list for strings without `strChoice` (`master:orientation`, `render:cm_sdr_eotf`, ...); `open: true` when free entry is allowed (`general:layout` `lua:<name>`) | section 3.3 |
| `nullable` / `null_value` | sentinel handling (`-1`, `"[[EMPTY]]"`, `"[[Auto]]"`), plus `null_label` ("Inherit", "Auto") | section 3.4 |
| `range` | min/max/step override (vec2 ranges from source; slider step; `soft_max` for INT_MAX ints) | section 1.3, 3.5 |
| `unit` | "px", "ms", "deg", "%" - for display only | description text ("in ms", "in px", "layout px") |
| `depends_on` | `{option, value}` to grey out (e.g. `input:scroll_points` needs `accel_profile=custom`; `general:extend_border_grab_area` needs `resize_on_border`) | description text "only used when ..." |
| `restart` | `"hyprland"` \| `"monitor-reload"` \| `"xwayland"` | wiki regex, hand-verified |
| `visibility` | `"default"` \| `"advanced"` \| `"hidden"` | section 3.1 |
| `group` / `order` | subsection and ordering inside a page when the stub tree isn't enough (e.g. put `general:col.*` under "Borders") | hand |
| `deprecated_in` / `renamed_from` | keep pages stable across versions | version diff |
| `type_override` | only for the Color-vs-String ambiguity when the generator ran without source | section 1.4 R11 |

Overlay validation: a test that every overlay key exists in the current generated schema, and that
every option flagged by the automatic heuristics (map-less int with `max<=6`, `[a/b/c]` in
description, sentinel default, vec2, css_gaps, font_weight, string with `font`/`monitor`/`regex`/`file`
in the name/description) has at least a `widget` or `labels` entry - this is exactly the 61-option
list in `option-schema.coverage.json` (`confident: false`).

### 6.3 Runtime

- Page structure from `path` (stub tree): 21 top-level sections, 16 subsections.
- Current values from `hyprctl -j getoption` per option (colon names), parsed by `type`;
  `is_default = value == default`, `is_set = set`.
- After a save/reload, re-poll (`configreloaded` IPC event).
- Never trust `descriptions.current`.
