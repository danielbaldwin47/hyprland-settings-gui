## 0. Global picture

* `hl` is a plain Lua table built in `Internal::registerBindingsImpl` (REG:81-97). Sub-tables: `hl.dsp` (+ `cursor`, `group`, `window`, `workspace`), `hl.layout`, `hl.notification`, `hl.plugin`. `print` is overridden to log to the Hyprland log (REG:14-27, 96-97).
* Full member list (STUB:820-868 `HL.API`): `animation bind clear_crashed_lockscreen config curve define_submap device dispatch env exec_cmd exec_scheduled_prop_refresh_immediately gesture get_active_monitor get_active_special_workspace get_active_window get_active_workspace get_config get_current_submap get_cursor_pos get_last_window get_last_workspace get_layers get_loaded_plugins get_monitor get_monitor_at get_monitor_at_cursor get_monitors get_urgent_window get_window get_windows get_workspace get_workspace_windows get_workspaces is_key_down layer_rule monitor on permission timer unbind version window_rule workspace_rule` + namespaces `dsp layout notification plugin`.
* **Reload model** (CM:634-760 `reload()`): on every reload Hyprland (1) syntax-checks the main file, then (2) resets *everything*: animation tree, workspace rules, monitor rules, all window/layer rules, gestures, timers, Lua layouts, device configs, plugin list, event handlers, all keybinds (`clearKeybinds`), then re-inits the Lua state (`reinitLuaState`) and resets every config value to default (`v.second->reset(); v.second->resetSetByUser()`), then re-executes `hyprland.lua` top to bottom (CM:699-751). Consequence: **the config file is the whole truth; nothing persists across reloads except what the file re-declares** (exceptions: `hl.env` and `hl.permission`, see below). Reload triggers: file watcher on the main file and every `require()`d file (CM:416-419, 561), or `hyprctl reload`.
* Files: main config `$XDG_CONFIG_HOME/hypr/hyprland.lua` (WIKI Start.md:10-14); split via `require("dir/file")`, `require("dir.file")`, wildcard `require("./stuff/*")`, absolute paths (WIKI Start.md:44-62; CM:215-356 implements a protected `require` and keeps the original as `__require`).
* Type-error policy: `hl.*` argument/type errors are *collected* (`addError`) and shown in the error overlay but do **not** abort the file; Lua runtime errors abort the current file; syntax errors abort the reload (WIKI Start.md:137-150; CM:746-750, 783).
* Value grammar shared by many entries (TYPES): 
  * **int** accepts integer or boolean (`true`→1) and, for enum-mapped ints, an enum *string* (`LuaConfigInt.cpp:9-40`) — this is why the stubs type most ints as `integer|boolean`.
  * **float** number|boolean; **string**; **bool**.
  * **color** = string: `"#rgb"`, `"#rrggbb"`, `"#rrggbbaa"`, `"rgba(hex8)"`, `"rgba(r,g,b,a)"`, `"rgb(hex6)"`, `"rgb(r,g,b)"`, `"0xAARRGGBB"`, or a plain decimal number (Lua numeric literals like `0xee1a1a1a` work because `lua_tostring` yields the decimal digits and `parseColor` accepts pure numbers) (`ParserUtils.cpp:23-131`, `LuaConfigColor.cpp`).
  * **gradient** (`HL.Gradient`, STUB:398) = a color string **or** `{ colors = { "<color>", … }, angle? = <degrees> }` (`LuaConfigGradient.cpp:16-77`; angle stored as radians).
  * **css_gap** (`HL.CssGap`, STUB:397) = integer **or** `{ top?, right?, bottom?, left? }` (missing sides default 0, `LuaConfigCssGap.cpp:14-63`).
  * **vec2** (`HL.Vec2Like`, STUB:396) = `{x, y}` array **or** string `"x y"` / `"x, y"` (`LuaConfigVec2.cpp:10-45`; note: **`{x=…, y=…}` is listed in the stub alias but the parser only reads array indices 1 and 2** — open question Q3).
  * **expression vec2** (window-rule `move`/`size`/`min_size`/`max_size`) = `{ "expr", "expr" }` with numbers or strings, or a single string (`LuaConfigExpressionVec2.cpp:8-45`).
  * **font_weight** = integer ≥0 or preset name (`LuaConfigFontWeight.cpp:16-40`; presets listed WIKI Variables.md:52).

## 1. `hl.config(tbl)` — **DECL** (the core of the GUI)

* Signature: `config(config: HL.ConfigOpt): nil` (STUB:825). `HL.ConfigOpt` (STUB:1314-1335) has 21 optional top-level categories: `general decoration animations input gestures group misc binds xwayland opengl render cursor ecosystem debug layout dwindle master scrolling experimental input_capture quirks`, each an `HL.ConfigOpt.<Cat>` class with nested sub-classes (`general.col`, `general.snap`, `decoration.shadow/glow/blur/motion_blur`, `input.touchpad/touchdevice/virtualkeyboard/tablet/tablettool`, `gestures.scrolling`, `group.col`, `group.groupbar`, `group.groupbar.col`, `misc.col`) (STUB:1337-1777).
* Semantics (CR:969-1018 `hlConfig`): a recursive `walk` over the table. For each string key it builds `prefix.key`; if that full key **is** a registered value it parses it in place; if it is not and the value is a table it recurses; otherwise `unknown config key` error. Non-string keys are skipped. **Only leaves you pass are touched → repeated `hl.config` calls MERGE** (confirmed by WIKI Variables.md:22-31: "each one will update just what you pass into it"; EX calls `hl.config` seven times, EX:86-226). Within a single reload, later calls override earlier ones for the same key. Across reloads everything resets to default first (§0), so *omitting a key = default*.
* Live changes: when called at runtime (keybind/timer/event callback), a prop refresh is scheduled with the value's `refreshBits()` (CR:1007-1008), so `hl.config` is a legitimate instant-apply channel via `hyprctl eval`/repl.
* Key universe: 353 dotted keys, identical set to `hyprctl -j descriptions` after `:`→`.` (CM:1136-1141 `luaConfigValueName` replaces `:`→`.` and `-`→`_`; verified: 353 stub `HL.ConfigKey` aliases = 353 `descriptions` entries). Per-key type table: `HL.ConfigValueTypes` (STUB:957-1312): 147 `boolean`, 72 `integer|boolean`, 32 `number|boolean`, 33 `string`, 16 `string|HL.Gradient`, 6 `HL.Vec2Like`, 3 `integer|HL.CssGap`, 2 `integer|string` (font weights). `descriptions` additionally supplies `default/current/min/max/map` (CTL) — the GUI's schema source.
* Extra keys not in `HL.ConfigOpt`: `autogenerated` (top-level int, CM:414; `hl.config({ autogenerated = true })` in the generated header) and `plugin.<name>.<opt>` values registered by plugins (CM:1147-1163, WIKI Plugins/Using-Plugins.md:101-109).
* Example (EX:86-131 abridged):
```lua
hl.config({
  general = { gaps_in = 5, gaps_out = 20, border_size = 2,
    col = { active_border = { colors = {"rgba(33ccffee)", "rgba(00ff99ee)"}, angle = 45 },
            inactive_border = "rgba(595959aa)" },
    layout = "dwindle" },
  decoration = { rounding = 10, shadow = { enabled = true, range = 4, color = 0xee1a1a1a },
                 blur = { enabled = true, size = 3, passes = 1, vibrancy = 0.1696 } },
})
```

## 2. `hl.get_config(key)` — **SCRIPT** (read-back helper)

* `get_config(key: HL.ConfigKey|string): any, string?` (STUB:837). Accepts dotted or legacy `:` keys (CR:1020-1044). Returns the value pushed by its parser: bool/int/float/string; css_gap → `{top,right,bottom,left}`; gradient → `{ colors = {...}, angle = ... }`; vec2 → `{ [1]=x,[2]=y, x=..., y=... }` (TYPES `push()`); unknown key → `nil, "unknown config key '…'"`. Wiki example toggling `general.gaps_in` at runtime (WIKI Expanding-functionality.md:107-142).

## 3. `hl.monitor(spec)` — **DECL**

* `monitor(spec: HL.MonitorSpec): nil` (STUB:853). `HL.MonitorSpec` (STUB:571-595): required `output: string`; optional `mode string ("preferred"|"highres"|"highrr"|"maxwidth"|"WxH@Hz"|"modeline …")`, `position string ("auto", "auto-left/right/up/down", "auto-center-*", "XxY")`, `scale string|number ("auto"|1.5)`, `disabled bool`, `transform int 0-7`, `mirror string`, `bitdepth int (8|10)`, `cm string`, `sdr_eotf string`, `sdrbrightness float`, `sdrsaturation float`, `vrr int -1..3`, `icc string`, `reserved`/`reserved_area css_gap` (aliases), `supports_wide_color int -1..1`, `supports_hdr int -1..1`, `sdr_min_luminance float`, `sdr_max_luminance int`, `min_luminance float`, `max_luminance int`, `max_avg_luminance int`. Field parsers/defaults/ranges: CR:81-178 `MONITOR_FIELDS`; docs & special values: WIKI Monitors.md:105-234.
* Semantics (CR:1103-1165): `output` is required and must be a string (`""` = fallback rule, `"desc:…"` = by description). **If a rule with the same `output` already exists in this reload it is loaded first and then patched** (`existing → parser.rule() = *existing`), and `CMonitorRuleManager::add` erases any rule with the same name before appending (`MonitorRuleManager.cpp:37-42`) → **repeat calls for the same output MERGE field-wise; last write per field wins**. Schedules `REFRESH_MONITOR_STATES`.
* Example: `hl.monitor({ output = "DP-1", mode = "1920x1080@144", position = "0x0", scale = 1 })` (WIKI Monitors.md:26-31); fallback `hl.monitor({ output = "", mode = "preferred", position = "auto", scale = "auto" })` (EX:18-23).

## 4. `hl.bind(keys, dispatcher, opts?)` → `HL.Keybind` — **DECL+SCRIPT**

* `bind(keys: string, dispatcher: HL.Dispatcher|function, opts?: HL.BindOptions): HL.Keybind` (STUB:822).
* **Key string grammar** (TL:30-130 `parseKeyString`): tokens split on `+`, trimmed. Leading tokens that are modifiers → modmask; modifier names accepted: `SHIFT`, `CAPS`, `CTRL|CONTROL`, `ALT|MOD1`, `MOD2`, `MOD3`, `SUPER|WIN|LOGO|MOD4|META`, `MOD5` (case-sensitive as written; TL:30-49). Modifiers must precede keys. Then either exactly one *special sym* — `mouse_down|mouse_up|mouse_left|mouse_right`, `mouse:<code>`, `switch:[on:|off:]<name>` — which cannot be combined with other keys, or one or more keysyms: `code:<n>` keycode or an XKB keysym name resolved case-insensitively via `xkb_keysym_from_name` (`Enter` is rejected with a hint to use `Return`). Whole string `"catchall"` = catch-all (only inside submaps, TL:151-152). The literal string is kept as `displayKey` (TL:157) and shown by `hyprctl binds`. Wiki: Binds.md:10-62, 115-162, 441-450.
* **Dispatcher argument**: a dispatcher userdata from `hl.dsp.*` **or a Lua function** (TL:148-149; REG:62-89 registers a `__lua` handler that pcall's the ref with a keybind timeout). A function may return `{ ok?, error?, pass_event? }` (REG:31-52). Functions are the escape hatch; the GUI should treat function-valued binds as opaque/user.lua.
* **`HL.BindOptions`** (STUB:437-453; parsing TL:159-251): `repeating`, `locked`, `release`, `non_consuming`, `auto_consuming` (parsed TL:192, *missing from stub*), `transparent`, `ignore_mods`, `dont_inhibit`, `long_press`, `submap_universal`, `click`, `drag` (both imply `release`; mutually exclusive), `description`/`desc` string, `device = { inclusive? = bool (default true), list? = {string…} }`, `allow_input_capture`. Constraints: `long_press`/`release` incompatible with `repeating` (TL:223-224). **`mouse = true`** appears in EX:290-291 and WIKI Binds.md:89,223-259 but **is not read by `hlBind`** (no `getBool("mouse")`; `kb.mouse` is never set) — the `drag()`/`resize()` dispatchers work on their own via `dsp_mouseDrag/dsp_mouseResize` (DSP:681-697); harmless no-op today (open question Q1).
* Returned handle `HL.Keybind` (STUB:640-672): methods `set_enabled(bool)`, `is_enabled()`, `remove()`, `unbind()`; read fields `key, modmask, keycode, display_key, submap, handler, arg, description, repeating, locked, release, click, drag, …`.
* Semantics: **append**; every call adds a keybind (`addKeybind`, KeybindManager.cpp:187-195); duplicates all fire in file order (WIKI Binds.md:164-177). Binds are cleared and rebuilt on every reload (§0). Bind inside `hl.define_submap` gets that submap.
* Example (EX:257-276): `hl.bind(mainMod .. " + Q", hl.dsp.exec_cmd(terminal))`, `hl.bind("XF86AudioRaiseVolume", hl.dsp.exec_cmd("wpctl …"), { locked = true, repeating = true })`.

### 4a. `hl.dsp.*` dispatcher namespaces — **DECL** (arguments are plain data)

Argument validation happens at construction time (config error). ## 5. `hl.unbind(keys)` — **SCRIPT** (mostly for runtime/`hyprctl eval`)

* `unbind(key: string): nil` (STUB:868). `"all"` clears every keybind (TL:404-408); otherwise `removeKeybind(displayKeys)` erases binds whose `displayKey` equals the string exactly **or** equals it after stripping spaces and lower-casing (KeybindManager.cpp:204-219) — i.e. **case- and whitespace-insensitive at v0.56.2**, contrary to WIKI Binds.md:539-546 which claims case-sensitivity (Q2). In a file-driven model `unbind` is redundant (binds don't survive reloads); it matters only for overriding binds declared by an earlier `require`d module in the same reload.

## 6. `hl.define_submap(name, [reset_to,] fn)` — **DECL** (structure) wrapping binds

* `define_submap(name: string, reset_or_fn: string|function, fn?: function): nil` (STUB:826; TL:258-287). Sets `m_currentSubmap` (+ optional auto-reset target submap when a bind inside fires) for the duration of `fn`, so every `hl.bind` inside belongs to the submap; nesting works by nesting calls (WIKI Binds.md:330-439). Callable multiple times for the same name → binds accumulate. `hl.dsp.submap(name)` enters, `hl.dsp.submap("reset")` leaves. `hl.get_current_submap()` reads state.
* Example: `hl.define_submap("resize", function() hl.bind("right", hl.dsp.window.resize({ x = 10, y = 0, relative = true }), { repeating = true }); hl.bind("escape", hl.dsp.submap("reset")) end)`.

## 7. `hl.window_rule(spec)` → `HL.WindowRule` — **DECL**

* `window_rule(spec: HL.WindowRuleSpec): HL.WindowRule` (STUB:871). Stub class only lists `enabled? bool`, `match? table<string,string|number|boolean>`, `name? string` (STUB:597-601); the effect fields are open-ended (static list + plugin-registered dynamic effects).
* **`match` props** (RULE `MATCH_PROP_STRINGS`, Rule.cpp:14-40; engines Rule.cpp:41-66): regex → `class`, `title`, `initial_class`, `initial_title`, `content`, `xdg_tag`, `namespace`(layers); bool → `float`, `xwayland`, `fullscreen`, `pin`, `focus`, `group`, `modal`; int → `fullscreen_state_internal`, `fullscreen_state_client`; workspace-selector → `workspace`; tag → `tag`. Regexes are RE2, `negative:` prefix negates (WIKI Window-Rules.md:85-93). Lua values: string, boolean or number (numbers are stringified as integers, CR:1200-1227). At least one prop is required by the wiki (Window-Rules.md:43-48).
* **Effect fields** — static table `WINDOW_RULE_EFFECT_DESCS` (INT:49-107, 57 entries) with Lua types: bool `float tile fullscreen maximize center pseudo no_initial_focus pin persistent_size allows_input dim_around decorate(default true) focus_on_activate keep_aspect_ratio nearest_neighbor no_anim no_blur no_dim no_focus no_follow_mouse no_max_size no_shadow no_shortcuts_inhibit opaque force_rgbx sync_fullscreen immediate xray render_unfocused no_screen_share no_vrr no_auto_hdr stay_focused confine_pointer`; string `fullscreen_state monitor workspace group suppress_event content animation idle_inhibit opacity tag tonemap`; expression-vec2 `move size max_size min_size`; int `no_close_for border_size rounding(0-20)`; float `scrolling_width rounding_power(1-10) scroll_mouse scroll_touchpad(0.01-10)`; gradient `border_color`. Unknown keys fall through to plugin-registered dynamic effects (`windowEffects()->get(key)`, CR:1242-1262). Meaning of each: WIKI Window-Rules.md:118-202 (note wiki also lists `no_wobble`, `no_xdg_drags` which are **not** in the static table — presumably dynamic; Q5).
* Semantics (CR:1167-1275): if `name` is non-empty and a rule with that name was already created *in this reload*, the **same rule object is reused and further match/effects are added to it** (`m_luaWindowRules[name]`) → repeated named calls MERGE (append effects); anonymous rules always create a new rule. `enabled` sets initial state. Registered in file order into the rule engine; evaluation: all named rules first, then anonymous, top to bottom, last match wins per effect (WIKI Window-Rules.md:314-341). Static effects apply once at open; dynamic re-evaluate on property change (Window-Rules.md:97-116, 156-158).
* Handle `HL.WindowRule` (STUB:788-791): `set_enabled(bool)`, `is_enabled()`. Only meaningful for named rules (WIKI Window-Rules.md:359-374).
* Example (EX:317-337):
```lua
local r = hl.window_rule({ name = "suppress-maximize-events", match = { class = ".*" }, suppress_event = "maximize" })
hl.window_rule({ name = "fix-xwayland-drags",
  match = { class = "^$", title = "^$", xwayland = true, float = true, fullscreen = false, pin = false },
  no_focus = true })
```

## 8. `hl.layer_rule(spec)` → `HL.LayerRule` — **DECL**

## 9. `hl.workspace_rule(spec)` → `HL.WorkspaceRule` — **DECL**

* `workspace_rule(spec: HL.WorkspaceRuleSpec): HL.WorkspaceRule` (STUB:872). `HL.WorkspaceRuleSpec` (STUB:603-622): required `workspace: string` (id, `name:x`, `special:x`, or a *selector* like `w[tv1]`, `r[2-4]`, `f[1]s[false]`, WIKI Workspace-Rules.md:19-52); optional `enabled bool`, `monitor string`, `default bool`, `persistent bool`, `gaps_in/gaps_out/float_gaps css_gap`, `border_size int`, `no_border/no_rounding/no_shadow bool`, `decorate bool`, `on_created_empty string`, `default_name string`, `layout string`, `animation string`, `layout_opts table<string,string|number|boolean>` (layout-specific, e.g. `{ orientation = "top" }` for master, `{ direction = "right" }` for scrolling; WIKI Master-Layout.md:76-88, Scrolling-Layout.md:41). Applying to a workspace merges every matching rule (WorkspaceRuleManager.cpp:34-45). Schedules monitor+window state refresh. Handle: `set_enabled/is_enabled` (STUB:815-818).
* Example: `hl.workspace_rule({ workspace = "name:coding", no_rounding = true, decorate = false, gaps_in = 0, gaps_out = 0, no_border = true, monitor = "DP-1" })` (WIKI Workspace-Rules.md:80).

## 10. `hl.curve(name, spec)` and `hl.animation(spec)` — **DECL**

* `curve(...)` (STUB:827 untyped). Two shapes (CR:278-388): `hl.curve(name, { type = "bezier", points = { {x0,y0}, {x1,y1} } })` (exactly 2 points, coords -1..2) or `hl.curve(name, { type = "spring", mass = n, stiffness = n, dampening = n })` (each > 0.5). Registered by name in the animation manager; re-declaring a name overwrites. `"default"` bezier and `"linear"` are pre-existing (EX:145 references `bezier = "default"` before any curve of that name is declared).
* `animation(...)` (STUB:821 untyped). Table (CR:390-476): `leaf: string` (must exist in the animation tree; tree listed WIKI Animations.md:41-76: `global > windows{In,Out,Move} | layers{In,Out} | fade{In,Out,Switch,Shadow,Glow,Dim,Layers{In,Out},Popups{In,Out},Dpms} | border | borderangle | shadowangle | glowangle | workspaces{In,Out} > specialWorkspace{In,Out} | zoomFactor | monitorAdded`), `enabled: bool` (if `false` nothing else is read and the node is set to disabled), `speed: float 0-100 (deciseconds)`, **exactly one of** `bezier = "<curve name>"` or `spring = "<curve name>"` (stored as `spring:<name>`), optional `style: string` validated per leaf (`"popin 87%"`, `"slide left"`, `"fade"`, `"slidefade 20%"`, `"loop"` for `*angle`). Note WIKI Animations.md:16,121,129 still shows `curve = …` — **the binding only reads `bezier`/`spring`; `curve` is ignored and yields "bezier or spring is required"** (Q4).
* Semantics: `setConfigForNode(leaf, …)` — one call per leaf; repeated calls for the same leaf OVERWRITE that node; children inherit from parents unless set. Tree reset on reload.
* Example (EX:136-161): `hl.curve("easeOutQuint", { type = "bezier", points = { {0.23, 1}, {0.32, 1} } })`, `hl.curve("easy", { type = "spring", mass = 1, stiffness = 238.1191, dampening = 24.21279333 })`, `hl.animation({ leaf = "windowsIn", enabled = true, speed = 4.1, spring = "easy", style = "popin 87%" })`.

## 11. `hl.gesture(spec)` — **DECL+SCRIPT**

* `gesture(spec: HL.GestureSpec): nil` (STUB:831). `HL.GestureSpec` (STUB:460-470) / parser CR:737-967: `fingers int 2-9` (req), `direction string` (req; `swipe|horizontal|vertical|left|right|up|down|pinch|pinchin|pinchout`, WIKI Gestures.md:33-42), `action` (req) = string `workspace|move|resize|special|close|float|fullscreen|cursor_zoom|cursorZoom|scroll_move|unset` **or** a Lua function **or** a table `{ start?, update?, finish? }` of functions (live gestures, WIKI Gestures.md:104-164); optional `mods string` (modmask via `stringToModMask`), `scale float 0.1-10`, `mode string` (float: `float|tile`; fullscreen: `maximize`; cursor_zoom: `mult|live`), `zoom_level` (string/number, cursor_zoom), `workspace_name` (special), `disable_inhibit bool`.
* Semantics: `addGesture(...)` keyed by (fingers, direction, mods, scale, disable_inhibit); `action = "unset"` removes a matching gesture; all gestures cleared on reload. Function actions are SCRIPT.
* Example: `hl.gesture({ fingers = 3, direction = "horizontal", action = "workspace" })` (EX:236-240).

## 12. `hl.device(spec)` — **DECL**

* `device(spec: HL.DeviceSpec): nil` (STUB:828). `HL.DeviceSpec` (STUB:508-553): required `name: string` (from `hyprctl devices`; spaces are converted to `-`, CR:1064) plus any of 43 per-device fields (`DEVICE_FIELDS` CR:230-274): keyboard `kb_layout kb_variant kb_model kb_options kb_rules kb_file numlock_by_default resolve_binds_by_sym repeat_rate(0-200) repeat_delay(0-2000)`; pointer/touchpad `sensitivity(-1..1) accel_profile natural_scroll left_handed scroll_method scroll_button(0-300) scroll_button_lock scroll_points scroll_factor(0-100) tap_button_map clickfinger_behavior middle_button_emulation tap_to_click tap_and_drag drag_lock(0-2) drag_3fg(0-2) disable_while_typing flip_x flip_y`; tablet/touch `transform rotation(0-359) output region_position region_size absolute_region_position relative_input active_area_position active_area_size`; virtual keyboard `share_states(0-2) release_pressed_on_close`; device-only `enabled`, `keybinds`, `tags` (comma-separated, used by per-device binds). Excluded per WIKI Devices.md:24-31: `force_no_accel`, window-management options like `follow_mouse`.
* Semantics (CR:1046-1101): stored in `m_deviceConfigs[name].values.insert_or_assign(key, …)` → **repeat calls for the same device MERGE field-wise**. Only fields set by the user override the global `input.*` value (CM:984-998 `setByUser()` check). Schedules `REFRESH_INPUT_DEVICES`.
* Example: `hl.device({ name = "epic-mouse-v1", sensitivity = -0.5 })` (EX:244-247).

## 13. `hl.env(name, value, dbus?)` — **DECL** (with a caveat)

* `env(...)` untyped in stub (STUB:829); parser CR:478-535: `hl.env(name: string, value: string, dbus?: boolean)`. Calls `setenv` immediately; if `dbus == true` also runs `systemctl --user import-environment NAME && dbus-update-activation-environment --systemd NAME` (exec-once on first launch, immediate on reload). On reload, if the variable already equals `value` nothing happens; a *changed* value is re-exported, but **a removed `hl.env` line does not unset the variable** (no reset path) → set-only semantics; a real removal needs a restart. Third arg `dbus` is undocumented in the wiki (Environment-variables.md only shows two args) but present in source.
* Example: `hl.env("XCURSOR_SIZE", "24")` (EX:58-59); `hl.env("SSH_AUTH_SOCK", os.getenv("XDG_RUNTIME_DIR").."/ssh-agent.socket")` (WIKI Environment-variables.md:29-30).

## 14. `hl.exec_cmd(cmd, rules?)` and autostart via `hl.on("hyprland.start", fn)` — **DECL** (autostart list) / **SCRIPT** (general use)

* `exec_cmd(cmd: string, rules?: table<string,string|number|boolean>): nil` (STUB:830; TL:321-335). Spawns via the executor immediately (async, `sh -c`); optional `rules` is a window-rule effect table (`buildRuleFromTable`, `LuaBindingsInternal.cpp:509-573`, accepts `floating` as alias of `float`) applied to windows of the spawned PID. **A top-level `hl.exec_cmd` runs on every reload** (the file is re-executed, §0) — this is the old `exec`. 
* The old `exec-once` is `hl.on("hyprland.start", function() hl.exec_cmd("waybar") … end)` (WIKI Autostart.md:10-21; EX:45-49). `hyprland.start` is emitted once by the compositor (EV:165) and handlers are cleared and re-registered on each reload (CM:711), so a handler registered on a later reload never fires. `hyprland.shutdown` is the mirror (EV:166).
* For the GUI: an "autostart" entity = ordered list of `{ cmd, once: bool, rules? }`; `once=true` → emit inside the single `hl.on("hyprland.start", …)` block; `once=false` → top-level `hl.exec_cmd`.

## 15. `hl.permission(spec)` — **DECL** (restart-only)

* `permission(spec: HL.PermissionSpec): nil` (STUB:855). Two call shapes (CR:556-622): table `{ binary = "<regex>", type, mode }` (`target` accepted as alias for `binary`) or positional `hl.permission(binary, type, mode)` (EX:76-78 uses positional). `type` ∈ `screencopy | cursorpos | plugin | keyboard|keeb | input-capture`; `mode` ∈ `ask | allow | deny`. **Only applied on first launch** (`if (mgr->isFirstLaunch()) addConfigPermissionRule`) → changes need a Hyprland restart (WIKI Permissions.md:28-30; EX:69-72). ## 16. `hl.plugin` — `hl.plugin.load(path)` **DECL**; `hl.plugin.<ns>.<fn>(…)` **SCRIPT**

* `hl.plugin.load(path: string)` (CR:537-554; STUB:949-952 `HL.PluginNamespace` = `load fun(...)` + `[string] any`). Appends to `m_registeredPlugins`; the list is cleared on each reload and diffed against loaded plugins in `postConfigReload → handlePluginLoads` (CM:1117-1130), which loads/unloads accordingly and re-reloads the config if the set changed. ## 17. `hl.layout.register(name, provider)` — **SCRIPT**

## Implications for the config model (short)

1. Because every reload starts from defaults and replays the file, the app never needs "delete" primitives (`unbind`, `unset`) in generated modules — omission *is* deletion — **except** `hl.env` (sticky) and `hl.permission` (restart).
2. `hl.config` merge semantics allow one generated module per section, each with its own `hl.config({ <section> = {...} })`; ordering only matters for identical keys.
3. Entities with natural identity for merge-by-key: monitor (`output`), device (`name`), workspace rule (`workspace`), named window/layer rule (`name`), animation (`leaf`), curve (`name`). Binds and anonymous rules are ordered lists.
4. Serialise dispatchers as `(namespace path, args table)`; type checks are done at construction, so the app can validate by mirroring §4a.
5. Function-valued fields (bind action, gesture action, `hl.on` handlers other than the autostart block, `hl.layout.register`, timers) mark a construct as belonging to `user.lua`.
6. Schema source: `hyprctl -j descriptions` (353 keys, defaults/min/max/map) + `HL.ConfigValueTypes` for Lua-side types (gradient/css_gap/vec2 vs plain) + the field tables in CR/INT for entities.
